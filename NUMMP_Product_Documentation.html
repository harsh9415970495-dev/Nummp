NUMMP: National Unified Material Master Platform

Complete Technical & Product Documentation (Hinglish)

"One Nation – One Material Code"

1. Project Ka Main Idea (Executive Summary)

NUMMP ek AI-powered platform hai jiska ultimate goal alag-alag CPSEs (Central Public Sector Enterprises) jaise CPCL, IOCL, ONGC, BPCL ke material codes ko ek single identity ke under lana hai.

Kyunki ek hi item (jaise Pipe ya Valve) alag-alag companies mein alag naam, alag units, aur alag format mein store hota hai, is platform ka kaam NLP, Semantic AI, Machine Learning aur Engineering Rules ka use karke in "alag dikhne wale" materials ko pehchanna aur unko ek unified Common National Material Code (CNMC) se link karna hai.

2. Problem aur Uska Solution Detail Mein

🔴 The Problem (Samasya Kya Hai?)

Har CPSE ka apna ERP/SAP system hota hai. Agar CPCL ne ek material ka naam HEX BLT SS316 M12X50 rakha hai, toh ho sakta hai IOCL ne usi same bolt ka naam BOLT, HEXAGONAL, STAINLESS STEEL 316, 12MM DIA X 50MM LG rakha ho. Iski wajah se:

  • Duplicate Inventory: Pata hi nahi chalta ki same item dusre plant mein pada hai.
  • Bulk Buying nahi hoti: Agar sab alag-alag kharidenge toh price negotiation nahi milta.
  • Normal Search Fail: Keyword search isme fail ho jati hai kyunki naam completely alag likhe hue hain.

🟢 The Solution (Hamara AI Platform)

NUMMP platform purane codes ko delete ya replace nahi karta. Ye ek central "Hub" ki tarah act karta hai. Ye AI ka use karke material ke text ki meaning samajhta hai, uske andar chhupe attributes (jaise size, pressure rating) nikalta hai, aur unhe aapas mein compare karke unhe ek Central Code (CNMC) assign kar deta hai. Isse traceability bhi rehti hai aur ek unified view bhi mil jata hai.

User yahan dekh sakta hai ki Material A (CPCL ka) aur Material B (IOCL ka) aapas mein kitne percent match ho rahe hain aur unke specific attributes aapas mein kaise compare hote hain.

Ye kya karta hai: AI se hone wali bewakoofi (hallucination) ko rokna aur engineering safety lagana.

Ye page dikhata hai ki kaise hamare Hard-Conflict Veto rules kaam karte hain. Agar critical spec (jaise Pressure Rating) mismatch hota hai, toh platform automatic mapping ko block kar deta hai, bhale hi AI ka similarity score 99% kyun na ho.

👥 5. Human-in-the-Loop Reviews (/app/reviews)

Ye kya karta hai: AI jo decide nahi kar pata, use Insaan (Expert) ke paas bhejna.

Yahan expert ek beautiful Side-by-Side Comparison screen dekhta hai jahan AI batata hai ki usko kyun lagta hai ye same hai aur kya conflict ho sakta hai. Expert apni knowledge se isko Approve, Reject ya Escalate kar sakta hai.

🏷️ 6. CNMC Registry (/app/cnmc)

Ye kya karta hai: Unified identity store karna aur track rakhna.

Details: Jab duplicates approve ho jate hain, toh unko ek Common National Material Code (jaise NMC-BRG-000452) de diya jata hai. Is page par CNMC ki list hoti hai aur har CNMC ke andar click karne par pata chalta hai ki ye ek specific material kin-kin alag-alag CPSEs mein kis-kis purane (legacy) code se mapped hai.

🏭 7. Cross-CPSE Virtual Warehouse (/app/inventory)

Ye kya karta hai: Procurement optimize karna aur stock search karna.

Details: Ye system ka sabse faaydemand feature hai. Agar BPCL ko ek urgent Valve chahiye, toh naya kharidne ke bajaye, wo is page par search karke dekh sakte hain ki ONGC ya IOCL ke kis plant mein ye same Valve surplus (extra) pada hua hai aur wo transfer request generate kar sakte hain.

5. Full Technical Architecture & Tech Flow (Backend Structure)

Hamara system ek Hub-and-Spoke Architecture follow karta hai. NUMMP central hub hai, aur baaki sabhi ERP (SAP) systems uske spokes hain.

💻 Technology Stack (Tech Stack Kya Use Hua Hai?)

Layer Technologies Used Reason (Kyun Use Hua?)
Frontend / UI Next.js (React), Tailwind CSS, Framer Motion Fast, scalable, SEO friendly aur Framer Motion se premium animations milti hain (jaise Login page ka glassmorphism).
Backend APIs Python, FastAPI, Celery FastAPI async processing mein fastest hai. Celery background mein lakho records ko match karne ka heavy data processing kaam karta hai.
AI & NLP Core Hugging Face Transformers (Sentence-BERT), spaCy Sentence-BERT texts ka matlab (semantics) samajhne aur embeddings banane ke liye best hai. spaCy custom NER (Entity extraction) ke liye.
Vector Search FAISS / Milvus Jab lakho records honge, toh normal database search slow ho jayega. FAISS Approximate Nearest Neighbor (ANN) search karke milliseconds mein similar records nikalta hai.
Database PostgreSQL, JSONB Master data relational format mein rakha jata hai aur specific engineering schemas ko dynamic rakhne ke liye JSONB use hota hai.

⚙️ Pura Tech Pipeline Flow (Kaise data process hota hai?)

  1. Ingestion (Data Aana): ERP systems se file ya API ke through raw material data NUMMP backend mein aata hai.
  2. Data Cleaning (Safai): Ek custom Python script kachre (noise), extra spaces aur ajeeb symbols ko hatati hai. UOM (Units of Measure) library jaise pint inch ko mm mein normalize karti hai.
  3. NLP Feature Extraction: spaCy model run hota hai jo text mein se categories aur dimensions nikalta hai.
  4. Semantic Embedding Generation: Sentence-BERT us pure saaf kiye hue description ko 384-dimension (ya 768-dimension) numeric vectors mein badal deta hai.
  5. Vector Match & Candidate Retrieval: FAISS database in vectors ko compare karta hai (Cosine Similarity) aur top 5 ya 10 matches retrieve karta hai.
  6. Composite Scoring & ML Classification: Ek Machine Learning classifier model (jaise XGBoost) in matches par ek final Confidence Score lagata hai jo text similarity aur attribute match ka weighted average hota hai.
  7. Engineering Rule Engine (Guardrails): Agar confidence score 95% bhi ho, toh Rule Engine check karta hai. Agar Hard Rules (jaise Pressure Rating mismatch) fail ho jate hain, toh engine automatically score ignore karke use block karta hai.
  8. Decision Routing:
    • Score ≥ 92% ➡️ Auto-Harmonize (Sidha CNMC assign hota hai).
    • 75% - 91% ➡️ Human Review Dashboard mein bheja jata hai.
    • < 75% ➡️ Unique variant mark karke reject kar diya jata hai.
